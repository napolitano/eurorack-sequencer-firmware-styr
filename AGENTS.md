# AGENTS.md — Styr development guidance

Styr is an experimental modernization of the MIT-licensed Westlicht Performer firmware. Preserve behavior unless a task explicitly changes it, and keep firmware, simulator and tests on the same sequencer implementation.

## Repository map

- `src/sequencer/` — **the Styr product implementation**
  - `engine/` — realtime sequencing, clocking, routing and generators
  - `model/` — projects, tracks, sequences, persistence and settings
  - `ui/` — pages, controllers and painters
  - `platform/stm32/` — hardware-only drivers, HAL and OS adapter
  - `main.cpp` — embedded application entry point
- `src/simulator/` — host-side simulator. It is a verification host for `src/sequencer`, not a separate implementation.
- `src/shared/` — small generic support layer only (`core/`, `os/`). Do not place sequencer product logic here merely because the simulator uses it.
- `src/bootloader/`, `src/hwconfig/`, `src/tester/` — separate embedded targets.
- `third_party/` — imported code. Do not move third-party code into `src/`.
- `test/` — PlatformIO + Unity tests for bootloader, shared core and sequencer product code.
- `src/simulator/tests/` — simulator-only CMake/CTest tests and host integration harnesses.
- `src/tools/fonts/` — standalone host-side font utilities. Font data belongs under `assets/fonts/`.
- `toolchain/` — PlatformIO board metadata, linker scripts and build/package integration. Product code does not belong here.
- `assets/` — first-party non-code inputs and generated source assets.

## Build ownership

Embedded targets use PlatformIO only:

```sh
pio run -e application
pio run -e application -t compiledb
pio run -e application -t upload
pio run -e application -t sd-update
```

Do not run `pio init --ide vscode`; VSCodium is treated as an editor and clangd consumes `compile_commands.json` generated by the `compiledb` target.

The simulator is an independent CMake project. Portable hosts use the `debug`/`release` presets; native Windows development uses the explicit `windows-ucrt64-debug`/`windows-ucrt64-release` MSYS2 presets. Neither build system may invoke the other, and STM32CubeCLT must not supply the simulator compiler.

## Current migration constraints

- The embedded baseline intentionally keeps GCC 6.3.1 and the pinned Westlicht `libopencm3` commit until the PlatformIO migration is proven equivalent.
- Dependency upgrades/replacements are separate changes. Do not modernize several dependencies while fixing a build-graph issue.
- Preserve the existing flash layout unless a task explicitly changes it:
  - bootloader `0x08000000`
  - hardware config `0x08008000`
  - application `0x08010000`
- Preserve the existing SD-card `UPDATE.DAT` format while the legacy bootloader is in use.
- LFO behavior is considered good and should not be casually refactored. The Acid Bassline generator is considered good enough and should remain regression-stable.
- The experimental Algorithmic Track was removed; do not reintroduce its model, engine, UI or project-format versions.

## Coding rules

- Put sequencer behavior under `src/sequencer`, even when the simulator executes it.
- Put code under `src/shared` only when it is genuinely generic and used by multiple targets.
- Keep platform-specific I/O behind the STM32 or simulator platform implementations.
- Persistent model changes require explicit project-version handling and tests.
- Be conservative with MCU RAM, static buffers and large object copies.
- Prefer regression tests before behavior-changing engine fixes.
- Do not alter bootloader or HWCONFIG behavior as a side effect of application work.

## Provenance

Moving or refactoring an inherited file does not change its provenance. Follow `docs/development/SOURCE_HEADERS.md`; third-party code keeps its own license, inherited Performer code retains MIT attribution in file headers, and Styr-native files keep their own authorship/SPDX metadata. First-party source files must keep their purpose/authorship/SPDX header current when code ownership changes.
