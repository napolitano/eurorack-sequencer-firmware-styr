# Documentation and Screenshot Pipeline

The repository-level capture guide is [`README_SCREENSHOTS.md`](../../../README_SCREENSHOTS.md). This page records the implementation and ownership rules for the maintained documentation tree.

## Markdown is source material

Markdown under `docs/manual/` is **not generated by the screenshot pipeline**. It is normal maintained documentation and must survive every screenshot run unchanged.

Initial Styr manual text should be written from two sources of truth:

1. the original PER|FORMER user documentation for inherited behaviour;
2. the current Styr implementation for anything that changed, was fixed or was added.

Text should be rewritten for Styr rather than copied mechanically. Feature and screen documents can then be edited normally without fear that the next image-generation run will overwrite them.

The upstream behavioral baseline is the official PER|FORMER user manual: <https://westlicht.github.io/performer/manual/>. It documents firmware 0.1.40 and therefore cannot be treated as authoritative for later Styr additions; current implementation and generated UI captures are used to resolve differences.

## Screenshot output ownership

The headless simulator writes user-manual images only to:

```text
docs/manual/assets/
```

Each capture has one maintained Markdown page below a functional subdirectory of:

```text
docs/manual/screens/
```

Styr-specific features keep a separate guide below `docs/manual/features/<feature>/` and reuse the same canonical images.

## Pixel scaling

The source framebuffer is 256×64 pixels. `Simulator::screenshot()` maps the LCD intensity to 8-bit grayscale and replicates each source pixel into an integer N×N block. The default documentation scale is 3× (768×192). Interpolation and anti-aliasing are intentionally excluded.

`Simulator::screenshotRegion()` uses the same integer replication for cropped UI components. The header and footer reference images use 256×10 native regions, producing 768×30 output at 3×.

## Coverage rule

Capture coverage is interaction-oriented rather than page-oriented. Relevant sublayers and modifier states are separate capture states. This includes Note/Curve layers, Shift direct-access functions, Quick Edit views, LFO functions and every waveform, generator parameters and Commit/Revert flow, plus shared display elements such as header and footer.

The consistency check is:

```bash
python3 toolchain/check_manual_screenshots.py
```

It enforces the one-to-one mapping between capture names, Markdown reference pages and expected PNG names. It validates documentation; it does not generate it.

## Generate images

```bash
cmake --build --preset <preset> --target manual-screenshots
```

For Windows UCRT64:

```powershell
cmake.exe --preset windows-ucrt64-debug
cmake.exe --build --preset windows-ucrt64-debug --target manual-screenshots
```

## Adding coverage

1. Establish a deterministic UI/model state in `src/simulator/tools/manual_screenshots.cpp`.
2. Prefer explicit model setup for fixture content and simulated input for the interaction being documented.
3. Add a stable semantic capture name.
4. Write the corresponding Markdown document manually, using upstream documentation and current code as factual inputs.
5. Add/update a feature README when the state belongs to a Styr-specific feature.
6. Run the mapping validator.
7. Generate the PNGs and inspect them visually before committing.
